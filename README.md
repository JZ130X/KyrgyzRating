# Kyrgyz Rating (Кыргыз Рейтинг) — модуль АПК

Предварительная индикативная оценка кредитоспособности компаний АПК Кыргызстана по скоркарду:
все данные вводятся измеримыми значениями (числа, «да/нет», списки) с документами-источниками,
категории и баллы программа получает по порогам методологии, отчёт для комитета составляет сама.

## Как открыть программу
- **Через GitHub Pages:** Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)` → Save.
  Через 1–2 минуты программа откроется по ссылке `https://<логин>.github.io/<репозиторий>/`.
- **Без интернета:** скачайте `index.html` и откройте двойным щелчком.
- **С общим архивом для команды:** скачайте `index.html` и `kg_agro_rating.py` в одну папку, выполните
  `python kg_agro_rating.py serve` и откройте http://127.0.0.1:8765 (архив, настройки и папка документов
  `kyrgyz_rating_files` — рядом с программой).

Оценки, настройки и документы хранятся в браузере пользователя (или на сервере в режиме `serve`), на GitHub не попадают.

## Исходный код
- `python/parts/*.py` — части движка; `python/build.sh` собирает `kg_agro_rating.py`.
- `web/src` — интерфейс (React + Vite); `engine.js` — построчный порт Python-движка, правила берутся из `config.json`
  (выгружается командой export-config). Сборка: `npm install && npx vite build` → `web/dist/index.html` (его копия — `index.html` в корне репозитория).
- `tools/` — сверка Python ↔ JS (`gen_cases.py`, `run_js.mjs`, `compare.py`: полный результат совпадает побитово;
  `process_parity.py`: правила комитета, рейтинговые действия и мониторинг; `period_parity.py`: годы и даты отчётного
  периода и перенос на следующий год), сквозные проверки интерфейса в Chrome (`e2e.py`, `e2e_process.py` — документы
  и комитет, `e2e_period.py` — отчётный период; все с `--server`; `e2e_nbkr.py бюллетень.xls` — загрузка бюллетеня
  в браузере: ставки, прочитанные JS, совпадают с Python).
- `manual/` — руководство: `guide.md`, скриншоты (`shoot.py`), сборка Word (`build_docx.js`).
- `video/` — видеоинструкция: `scenario.py` проходит программу в Chrome (пример «Ала-Тоо Сүт», курсор, подписи,
  ускоренный ввод; в конце сверяет оценку с Python), `narration.py` — текст диктора (голос RHVoice «Александр»,
  пакеты `rhvoice rhvoice-russian`), `render.py` монтирует MP4 и дорожку диктора (ffmpeg). После изменений интерфейса:
  `python video/scenario.py && python video/render.py`.

## Отчётный период
- Первая группа профиля: дата оценки, последний полный финансовый год, дата баланса, тип отчётности. От них программа
  сама ставит годы в таблице «по годам» и годы/даты в подписях полей (метки «2026 г.», «на 31.12.2026», «2027 г.»,
  окна 36 месяцев и 5 лет от даты оценки); год ↔ дата баланса 31.12 связаны. Несогласованные даты — предупреждение,
  на расчёт не влияет.
- Следующий год: «Архив → Новая оценка → Следующий год» или кнопка в блоке периода: год +1, баланс +12 месяцев,
  таблица «по годам» сдвигается на столбец, профиль и реестры остаются, остальное вводится заново.

## Документы и комитет
- К каждому полю «Источник» и к профилю компании прикрепляются файлы (до 25 МБ). Имя файла в хранилище — SHA-256
  содержимого; на расчёт файлы не влияют. «Скачать досье (ZIP)» и «Архив → Скачать с документами (ZIP)» переносят их.
- Раздел «Комитет и мониторинг»: проверка вторым аналитиком, протокол с кворумом (3), конфликтом интересов и голосованием,
  рейтинговые действия, сроки пересмотра (12 месяцев; «На пересмотре» — 90 дней), отзыв. Python перепроверяет протокол
  каждой записи (`process_ok`), `archive-verify` — ещё и целостность файлов.

## Важно
- Оценки прежней версии программы (скоркард v0.3) показываются в архиве только для просмотра: пересчитать их нельзя — другой набор данных.
- Изменённые веса и пороги («Настройки») сохраняются вместе с каждой оценкой и отмечаются в отчёте.

## Рыночная ставка и нормализация процентов

Если эффективная ставка компании (проценты / средний долг) ниже 50% ключевой ставки НБКР или проценты не начислены
при долге, проценты для 4.2–4.4 и прогноза считаются по рыночной ставке. Ставка берётся по порядку:
1. поле профиля `mkt_rate` (ставка для отрасли за отчётный период) — только вместе с источником `s_mkt_rate`;
2. ставка подсектора из настроек: `settings.subsectors[<код>].market_rate` (хранится, только если отличается от общей);
3. ставка из бюллетеня НБКР (`settings.nbkr`), если он загружен: таблица IV.2.19 «новые кредиты в сомах» по отрасли
   подсектора (`subsectors[<код>].nbkr_sector`, по умолчанию: CRP, PRM, API, FSH → `agri`; DAI, MEA, FLR, OIL, FED, SUG,
   CTN, FRU → `ind`) за отчётный период компании: год → годовая ставка; LTM → 12 месяцев до месяца баланса;
   промежуточная → `interim_months` месяцев; ставка периода = среднее арифметическое помесячных ставок (так НБКР
   считает годовую: 39 из 40 годовых ставок бюллетеня №08/2026 равны среднему 12 месяцев, одна отличается на 0,03 п.п.;
   средневзвешенное по объёму отличается до 4,6 п.п.). Нет данных за период → предупреждение и общая ставка;
4. общая ставка `settings.market_rate` (методология: 16%).
Агрохолдинг без своей ставки и своей отрасли — Σ доля сегмента × ставка его подсектора (по тому же порядку).
В результате: `b4.int.market`, `market_src` (`input` / `sub` / `nbkr` / `segments` / `all`), `market_note` (источник),
`ic_actual` — покрытие по фактическим процентам (справочно). Код расчёта (`result_hash`) от этих полей не зависит.
Нормализация не уменьшает проценты: если рыночная ставка × средний долг не больше фактических процентов,
`recompute = false` и предупреждение. Если нормализация применена, а рыночная ставка ниже ключевой — предупреждение
о льготных программах в ставке.

### Бюллетень НБКР
«Настройки» → «Загрузить бюллетень НБКР» → «Применить». Файл (.xls/.xlsx с сайта НБКР; внутри — формат xlsx) читается
без интернета и без библиотек: Python — `zipfile` + `ElementTree` (`python/parts/fzzz_nbkr.py`), браузер —
`DecompressionStream` (`web/src/xlsx.js`). Из листа IV.2.19 берутся годовые и помесячные ставки и объёмы по отраслям
(сельское хозяйство, промышленность, заготовка и переработка, торговля, всего); IV.2.22 (портфель) — только справочно.
Старый двоичный формат Excel 97–2003 не читается: программа просит пересохранить файл как .xlsx. Бюллетень хранится
в настройках (`settings.nbkr`: `title`, `file`, `new.years/months`, `port.years`) и сохраняется вместе с каждой оценкой
в архиве — прежние оценки не пересчитываются по новым ставкам.
